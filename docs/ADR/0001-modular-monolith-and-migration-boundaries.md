# ADR 0001 · 模块化单体、证据保真与阶段边界

日期：2026-10-08。状态：**Proposed，待家长审查**。本ADR记录设计提议，不表示已批准开发或已发生数据迁移。

## 背景

数学有Node/SQLite、互动课程、家长批阅与宠物；英语有静态UI、V1/V2词条/复习/事件与本机记录保护。目标是统一账户、全科计划、报告、奖励与家园，同时保留两科课程和教学引擎。当前NAS的Linux4.4低于Node24官方glibc平台支持基线。

## 决策提案

| 编号 | 提议 | 理由/代价 |
| --- | --- | --- |
| D1 | npm workspaces模块化单体，一个React shell、一个Node writer、一份本地SQLite | 跨科事务简单，家庭部署成本低；接受单writer及小规模负载边界 |
| D2 | packages/contracts、platform、pets、ui、subjects/math/english与版本化content | 明确学科与平台依赖；新增科目不新增钱包或账户 |
| D3 | 数学迁移候选使用8e91154，另记录main1e8199d | 保留已完成的新证据与父母能力；用户需确认来源选择，本轮不合并旧仓库 |
| D4 | 学科payload先完整保留；原始bytes只读快照与转换报告必需 | 快速适配且防丢未知字段；派生索引可以重建，原始证据不能 |
| D5 | 客户端提交commands，server/授权parent生成证据；事件追加不可改 | 继承首答与提示语义，防伪金币；开放题人工审阅仍需等待 |
| D6 | Phase0只文档；Phase1–3只在批准后的合成/匿名环境适配，中央钱包Phase4另审 | 不把设计授权扩大为开发授权；真实切换后才能停止旧站写入 |
| D7 | 旧math钱包、旧english coins/XP、pet growth分别保存；不在Phase0兑换 | 尺度与账本完整性不同；Phase4策略需要单独批准并可审计 |
| D8 | 全科planner只协调预算，学科保留自己的复习/判分 | 数学证据链与英语间隔不同；backlog安全延后，休息无惩罚 |
| D9 | Tailscale Serve单一HTTPS origin，app会话/parent grants/CSRF仍需完整实现 | 私网不是应用权限；不启用Funnel，不暴露数据API |
| D10 | NAS先做兼容探针，Node24内核支持路径先决策再正式部署 | 容器不能升级内核；可能需要现代Linux执行环境或显式风险接受 |

## 没有选择的实现

iframe拼接不能统一可信事务与进度；大重写会破坏原教学与测试；微服务增加家庭部署运维；把全部payload立刻拆为细粒度SQL表增加迁移丢字段风险。未来可逐步规范化热点，但原始历史保留。

未选择历史币汇率、英语XP换币、奖励尺度、全自动AI评分、新复习算法、联网PK、主题版权素材再发布或生产部署主机变更。这些不包含在本轮工作成果里。

## 审查后需要明确的事项

1. 数学整合采用8e91154，是否保留与main的来源差异作为迁移说明；无需本轮合并旧repo。
2. 是否接受先用合成数据完成Phase1运行探针，再选定NAS实际支持路径。
3. 新app的单孩子账户/家庭成员授权、配对与家长PIN引导细节；不可只靠tailnet身份分角色。
4. 真实记录在哪里、何时只读备份与预览；不把未知字段静默丢掉。
5. Phase4前再讨论历史金币/XP/伙伴成长的政策，批准开账之前不实施。

## 生效与回退

批准后逐PR实现，验收见[PR计划](../phase-0/06-phased-pr-plan.md)。到Phase6前旧站仍是原学习事实源；新平台演练使用匿名数据。正式切换在停旧写、最终快照、逐字段对账、恢复演练和双设备验收后发生。上线后回退必须保存新产生的事件与新库，不仅是退代码版本。
